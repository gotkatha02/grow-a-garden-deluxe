The owner (Thai speaker) builds this game across many chats. Reply in Thai. Commit and push finished work to this repo; no zip files.

## Design rules (owner's, apply to every hero and system)
1. **12 Tails style.** Skill trees: Basic + Class A + Class B (two clearly different play styles) + Class C (12 nodes: Basic / A / B columns, unlocked at Lv 55 / 60 / 70 / 80 — squeezed to 51 / 52 / 54 / 56 by the Lv 60 cap, see Stats). Zigzag levelling between a row-1 skill and its partner. A and B must be different play styles (not the same kit with other numbers). Each C node is an upgrade of, or a new skill tied to, the Basic / A / B skill in the same row.
2. **No percent effects.** Use flat values (ATK +X, damage taken −X per hit, shield = level × n). Random chances become counters ("every 4th hit"). Exception (owner 2026-11-19): the item system may keep its percents and chances — special stats, item traits, refine success, drill holes, drop rates (items.js / ITEM_SYSTEM_TH.md). Owner 2026-11-22 (RO stats): runes may use RO-style percents too (race / element damage %, ATK % …); hero skills still may not.
3. **Skill power is written as ATK×n or MATK×n** (TAL was renamed MATK with the RO stats, 2026-11-22). The number shown already includes the hero's coefficient (`CHAR_COEF` in index.html).
4. **Attack speed (ASPD) follows Ragnarok** (owner 2026-11-22, replaces the old "fixed per character" rule): hero base `CHAR_ASPD` at AGI 1 / DEX 1, raised by AGI (÷250) and DEX (÷1000) and by items' ASPD %, then buffs (`aspd()`); cap 190.
5. **Balance:** no hero stronger than the others. Target bench score ≈ 2,050 at the Lv 60 cap (tank Rhino ≈ 1,880) — re-tuned 2026-11-22; the older notes below quote the Lv 99 era target 2,450 / 2,250. Two-way heroes are tested per branch (A alone, B alone) with an INT build (RO stats; was TAL).
6. **Pictures are the main effects, code VFX supports them.** Placeholder sprites are fine until real art arrives. Art prompts for ChatGPT: cartoon style matching the characters, one prompt per copy box, sent one at a time.
7. **Selling points (owner 2026-11-21).** (1) branch choice — skill points cannot cover the tree, (2) upgrading / customizing skills with gems — and every gem's effect must SHOW on the real skill (its look when used, its button, its tooltip and tree node), (3) diverse stat builds. New systems must deepen or surface one of these; generic power (refine, % stats) stays small. Audit + proposals: GAME_PILLARS_TH.md (owner picked item 2 = skill stars, built 2026-11-21; his angle: fixed ASPD + boss focus → the game's own hook is 're-tune your skills per boss', so every boss should pose one question a gem answers).

## Stats and damage (Ragnarok formulas, owner 2026-11-22 — RO_STATS_TH.md)
- **Level cap 60 (owner 2026-11-22 'ตัดที่60ก่อนตอนเปิดเกม ปรับเลเวลมอนที่มีตอนนี้ให้ตันแค่60ด้วย')** — level_cap.js (window.LVC, LV_CAP), details + tables in LEVEL_CAP_TH.md. Everything was designed on 1–99: WORLD levels (monsters, map bands, warp signs, bosses, item / material / relic levels) are spread over 1–60 by LVC.n (×0.6, maps/level-zones.js squeezes ZONE right after building it); the item system reads grades / ore tiers / zeny / potions / Star Ore through LVC.o (design level of a level) so a monster drops what it dropped before, item lvReq = LVC.nc (grade 1–9 = Lv 7 … 55); character GATES above 60 are squeezed by LVC.g (1–50 kept, 50–99 → 50–60): totem pole tiers Lv 52/54/56/58/60, C-gem tiers 52/54/56/58, CTIER_LV 51/52/54/56 (skill tree complete by 50 and skill holes 10–50 unchanged → same unlock order). Carving goods keep their design bands (SOCK_LV0). The character's per-level rules: RO points (below), hero bonus, 1 skill point / level. EXP keeps its curve shape via LVC.o (~21 kills at Lv 1 → ~98 for the last level). Saves: play levels above 60 come back at 60 (fitStats trims), saved items re-read lvReq from grade / base (items.js lvFix; storage + old gear market too). Test mode = a Lv 60 hero (presetAt scales PRESETS); bench / test-room dummies MON are Lv 38 / 52 / 44 (design 62 / 85 / 72 in MON_LV0). Every hero was re-tuned at Lv 60 (bench target ≈ 2,050, see rule 5 and the 'Lv 60 retune' note). New world content: write its level on the 1–99 design scale and convert with LVC.n, or write the new level directly and say so.
- **Stats: STR AGI VIT INT DEX LUK** (RO). Total = points + hero bonus + items / buffs. Old 12 Tails → RO: ATK→STR · TAL→INT · INT (SP / cast)→DEX · LCK→LUK · CHA removed (resist = VIT / INT, statuses we inflict = DEX vs monster VIT/2, buff length = skill level only) · DEF is no longer a stat (armour DEF + VIT/2 + AGI/5).
- **Points (RO):** 48 at Lv 1, Lv x → x+1 gives floor(x/5)+3 (555 at Lv 60) · raising x → x+1 costs floor((x−1)/10)+2 · max 99 (one stat ≈ 90 at Lv 60, the rest spread). Hero bonus (like RO job bonus) = floor((Lv−1) × rolled base × 0.0085) ≈ +18 total at Lv 60; the creation roll is hero base (`CLASS_BASE`, 6 stats summing 36) +1 ×3 −1 ×3 +1 all, clamp 3–12.
- **Derived (`derive()`):** ATK = STR + (STR/10)² + DEX/5 + LUK/5 (owl = ranged: DEX main) + weapon ATK + refine (+2/3/5/7 per +1 by weapon level) + flat ATK, × ATK % · MATK = INT + (INT/7)² + DEX/5 + LUK/5 + magic weapon MATK (+ refine) · HIT = Lv + DEX + LUK/3 · FLEE = Lv + AGI + LUK/5 · perfect dodge 1 + LUK/10 % · CRIT 1 + LUK×0.3 (target shield LUK/5), crit ×1.4 skips DEF and FLEE · DEF = armour + VIT/2 + AGI/5 · MDEF = items + INT + VIT/5 + DEX/5 + Lv/4 · MaxHP (300 + 14 Lv)(1 + VIT/100) · MaxSP (40 + 3 Lv)(1 + INT/100) · cast × (1 − DEX/150) · no stat changes cooldown or move speed any more (items / skills only).
- **Hit / miss:** hit % = 80 + HIT − target FLEE (5…95). Normal attacks and physical skills (incl. two-way 'x') can MISS; magic, DoT, crits and `o.sure` hits always land. Monsters: perfect dodge first, then their HIT vs our FLEE (−10 % FLEE per attacker after the 2nd); caster orbs are magic (MDEF, no dodge). Physical damage vs DEF, magic vs MDEF (35/65 formula `defAdjust`).
- Skill damage: physical = coefficient × ATK, magic / heal = coefficient × MATK (`D.patk` / `D.mag`). Two-way heroes (wolf, jaguar, owl, hippo, dragon, lion): normal attack = ATK only; magic-looking skills = MATK; physical-looking skills type 'x' = ATK 30% + MATK 70% (MIX in skill_rules.js); Basic-branch 'b' = the higher. Two-way heroes are benched with the INT preset (old name สายเวท still works), each branch alone.
- Monsters (`monStats`): 20 + 3 points a level spread by role into the six stats + DEF / MDEF; HP (536 + 20 Lv + 10 VIT) × 2.2, ATK (Lv + STR) × 1.86 (×2.2 / ×1.86 since the RO stats, same Lv 60 pacing: 20–31 hits to kill with gear, 15–23 to die), HIT = Lv + DEX (+60 % Lv for bosses), FLEE = Lv + AGI.
- Items: weapon ATK / MATK and armour DEF / MDEF are raw RO-scale numbers; STR … LUK bonuses are small (+1 … +2 a piece, `pairPut`); special stats include RO ones (HIT, FLEE, perfect dodge, ASPD %, cast %, ATK % / MATK %, damage vs race % `r_<race>`, vs element % `e_<el>`, element resistance % `x_<el>`). Orbs: STR AGI VIT INT DEX LUK DEF. Old saves convert once (`conv12`, `it.ro`, bag orbs, `ps._ro` = refund all stat points).

## Art prompts (what to write when the owner asks for an image or effect prompt)
- Look: friendly hand-painted chibi cartoon matching the game, thick clean dark-brown outlines, cel shading with 2–3 flat tones, soft cartoon glow, bright and warm. Not realistic, not painterly smoke, not 3D. Say this in every prompt.
- Always tell the owner to attach the campfire key art (style) and the hero's character sheet (look). Describe the hero's outfit in the prompt too.
- One prompt per copy box, English prompt, Thai explanation around it. No text / logo / watermark in images.
- Skill effects: ONE effect per image, transparent PNG background, empty space on every side. Never sprite sheets on magenta/green (cut-outs break and red/pink parts vanish). State the view: ground pieces = flat wide ellipse seen 3/4 top-down; streaks/slashes = side view pointing right; upright pieces (spirit, aura, dome) = flat base at the bottom.
- Skill icons: 4×3 sheet 1536×1024, rounded square with thick shiny gold frame, chibi hero acting the skill, background colour per branch, "each icon is a perfect square". Save the prompts as <HERO>_ICON_PROMPTS_TH.md with a slot → skill key table.
- Skill tree backgrounds: vertical 2:3, full-body hero in the lower middle, theme of the branch, top 15% kept simple, medium-light colours (icons sit on top). Basic = start of journey, A / B = their play style, C = legendary with the hero's giant spirit behind.
- Fixing a generated image: tell the owner to brush-select only the part to change in ChatGPT, one character at a time; whole-image edits redraw everything.
